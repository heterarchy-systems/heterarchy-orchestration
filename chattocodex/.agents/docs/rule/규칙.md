# HETERARCHY Orchestration 개발 규칙

## 목적

`heterarchy-orchestration`을 Main Chat과 N개의 Agent Runtime을 연결하는 안정적인 MCP / HTTP control-plane backend로 개발하고 리팩토링하기 위한 mandatory repository rules다.

이 문서는 PRD가 아니다. 현재 사용자 요청과 직접 관련된 touch-path만 변경한다.

## Authority

- Main-facing MCP / FastAPI, DAG, scheduling, Project/Folder/Team desired state, runtime provisioning은 Orchestration 책임이다.
- Broker `GroupCoordinator`가 실제 ConsumerGroup membership/generation을 authoritative하게 소유한다.
- Task ownership, lease, epoch, fencing, Broker term은 Broker authority다.
- Orchestration은 Broker authoritative state를 local database authority로 복제하지 않는다.
- GPT/Claude/CLI 같은 Provider runtime metadata를 Broker domain으로 밀어 넣지 않는다.

## Mandatory workflow

1. 기존 dirty worktree와 repository rules를 먼저 확인한다.
2. `00-overview.md`, `규칙.md`, touch-boundary numbered rules를 읽는다.
3. FastAPI/ORM/DI backend 작업은 `fastapi-skill`과 `dependency-injector-skill`을 함께 적용한다.
4. 기존 abstraction/library를 조사하고 재사용한다.
5. focused regression을 먼저 실행한다.
6. 변경 후 canonical `make ci`를 실행한다.
7. real integration claim은 별도 real E2E evidence가 있을 때만 한다.

## Pydantic v2 contract

- Named-field schema는 canonical `StrictSchemaModel`을 상속한다.
- Root-value schema는 canonical `StrictRootSchemaModel`을 상속한다.
- production schema에서 `BaseModel` / `RootModel` 직접 상속을 금지한다. canonical base module만 예외다.
- production schema에서 `pydantic.Field()` 직접 호출을 금지한다. canonical `described_field()` helper만 예외다.
- `described_field()`는 `description`을 필수 keyword로 받고 `default` / `default_factory` 인자를 제공하지 않는다.
- 실제 protocol/domain default는 annotation metadata와 분리하여 assignment로 표현한다.
- 설명 없는 Field metadata는 금지한다.
- top-level `list[T]` / `tuple[T, ...]` API/MCP contract는 named `StrictRootSchemaModel`로 감싼다.
- collection field가 parent named schema 내부에 있을 때는 collection annotation을 사용할 수 있다.
- repetitive optional-field serialization/exclude chain은 typed Pydantic filter/value object 또는 shared `model_exclude` helper로 응집한다. 단순 business branch를 reflection으로 숨기지 않는다.
- 이미 검증된 내부 DTO를 반복 `model_validate()`하지 않는다.

## Internal type rules

- 검증 완료 후 내부 command/snapshot/decision/result는 필요할 때 `@dataclass(frozen=True, slots=True, kw_only=True)`를 사용한다.
- 알려진 mapping shape를 `dict[str, Any]`로 service layer에 전달하지 않는다.
- partial/raw mapping은 `TypedDict` 또는 named narrow JSON value type을 사용한다.
- `Any`, broad cast, broad ignore, convenience Optional로 타입 결함을 숨기지 않는다.
- `None`은 실제 domain state일 때만 사용한다.

## FastAPI

- normal HTTP application/routing은 `FastAPI` + bounded-context `APIRouter`로 구성한다. 일반 route를 위해 Starlette application을 직접 만들지 않는다.
- low-level OAuth/ASGI/MCP compatibility 외에는 Starlette `Request` / `Route`를 HTTP application contract로 사용하지 않는다.
- route는 request extraction/validation/auth/mapping/delegation만 담당한다.
- lifecycle/resource ownership은 ASGI lifespan을 사용한다.
- application pool/client를 import time에 생성하지 않는다.
- async I/O request path는 `async def`를 사용하고 unavoidable blocking sync call은 Asyncer `asyncify` 경계로 보낸다. production `asyncio.to_thread`를 흩뿌리지 않는다.
- FastAPI의 Python-mode predecode가 strict JSON semantics를 깨는 body는 shared `model_validate_json()` dependency로 검증하며 strict를 낮추지 않는다.
- normal FastAPI JSON은 typed Pydantic response model/return type을 사용해 FastAPI/Pydantic의 직접 직렬화 경로를 우선한다. deprecated `ORJSONResponse` default를 설정하지 않는다.
- status/header/protocol 요구로 manual `Response`가 필요한 경계는 typed Pydantic model의 `model_dump_json()`을 사용한다. stdlib `json`, manual `JSONResponse`, deprecated `ORJSONResponse`를 production HTTP 코드에서 사용하지 않는다.
- `orjson`은 FastAPI 밖의 JSON hotspot에서 실제 필요성과 성능 이득이 확인된 경우에만 추가한다.
- blocking I/O를 event-loop에서 실행하지 않는다.
- user-controlled concurrency는 반드시 bound/backpressure를 가진다.

## Settings

- process configuration은 `pydantic-settings` `BaseSettings`로 읽는다.
- service/repository/route에서 `os.getenv`, `os.environ.get`, `os.environ[...]`로 configuration을 직접 읽지 않는다.
- subprocess에 inherited environment를 전달하기 위한 `os.environ.copy()`는 configuration parsing이 아니므로 허용한다.

## Dependency Injection

- `containers.DeclarativeContainer`를 composition root로 사용한다.
- application-lifetime expensive resource는 `providers.Resource`를 우선한다.
- repository/service의 request/unit-of-work assembly는 `providers.Factory`를 우선한다.
- `providers.Singleton`은 concurrency-safe application-scoped object에만 사용한다.
- SQLAlchemy `Session` / `AsyncSession`은 Singleton 금지다.
- domain/application code에서 Container import 또는 provider lookup을 하는 Service Locator pattern을 금지한다.
- FastAPI wiring에서 route decorator는 outer, `@inject`는 function 바로 위에 둔다.
- test dependency substitution은 provider override를 사용하고 production `if testing` branch를 만들지 않는다.

## PostgreSQL / SQLAlchemy

- 새 control-plane relational persistence의 canonical DB는 PostgreSQL이다.
- SQLite compatibility/fallback을 추가하지 않는다.
- SQLAlchemy 2.x ORM을 사용한다.
- async request path는 async engine/session API를 사용한다.
- engine/pool은 application lifespan, `AsyncSession`은 request/unit-of-work scope다.
- 하나의 `AsyncSession`을 concurrent tasks 사이에 공유하지 않는다.
- repository는 engine/configuration을 직접 생성하거나 environment를 읽지 않는다.
- transaction commit/rollback ownership을 application service/unit-of-work boundary에 명시한다.
- ORM entity를 HTTP/MCP response로 직접 노출하지 않는다.
- index/constraint는 query/invariant 근거가 있을 때 추가한다.

## MCP v2

- official MCP Python SDK v2 line을 유지한다. dependency resolution이 `mcp<2`로 silent downgrade하는 것을 금지한다.
- MCP v2 high-level official class는 `MCPServer`이며 existing official v2 transport/OAuth/tool contract를 우선 보존한다.
- standalone `fastmcp` package를 추가하지 않는다. official `mcp` v2 `MCPServer`로 통일한다.
- MCP tools는 transport adapter이고 workflow/authority policy를 재구현하지 않는다.

## Performance

- correctness와 evidence 없는 micro-optimization보다 구조적 비용을 먼저 제거한다.
- DB engine/pool은 재사용하고 session은 짧게 소유한다.
- N+1, repeated full scans, repeated validation/serialization, duplicated mapping pass, unbounded collection을 우선 조사한다.
- response/list endpoint에는 explicit bound/pagination을 둔다.
- expensive shared clients/resources를 request마다 새로 만들지 않는다.
- performance 개선 claim은 benchmark/profiling 또는 명백한 allocation/I/O 제거 근거를 남긴다.

## Worktree / change discipline

- pre-existing dirty file을 reset/clean/overwrite하지 않는다.
- concurrent/unrelated 변경을 발견하면 현재 내용을 다시 읽고 patch한다.
- obsolete compatibility는 현재 contract가 허용하는 범위에서 삭제한다. hidden compatibility를 새로 만들지 않는다.
- 사용자 요청 없이 commit/push하지 않는다.

## Verification / completion

- `rule_check`: rule/skill/schema mechanical contract.
- `backend_check`: FastAPI / async / settings / typed JSON response / Any runtime contract.
- `format_check`: Ruff format + lint.
- `type_checking`: Pyrefly.
- `test`: repository unit/integration harness.
- `make ci`: mandatory aggregate gate.
- cross-language Broker/MCP real integration claim은 `broker_e2e` 같은 real gate를 별도로 실행한다.
- 테스트를 실행하지 않았으면 `VERIFIED`라고 부르지 않는다.
- mandatory gate가 실패했으면 성공으로 보고하지 않는다. pre-existing/change-induced/environment를 구분한다.
